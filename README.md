# Drilling Progress

Python дата боловсруулалт + GitHub Pages dashboard. Drone Track / Mapping төслийн адил `main` руу push хийхэд `dist/` сайт GitHub Actions-аар нийтлэгдэнэ.

Repository: https://github.com/SysMargad/Drilling-Progress

GitHub Pages: https://sysmargad.github.io/Drilling-Progress/

## Python ажиллуулах

Python 3.10+ шаардлагатай. Local CSV/XLSX уншихад нэмэлт package хэрэггүй.

```powershell
py -3 drilling_sync.py
py -3 drilling_sync.py --watch 300 --serve
```

Local dashboard: http://127.0.0.1:4318. `start-dashboard.cmd` ашиглаж болно.

`input/` нь 2026.10.14-нд Drive-ээс уншсан эхний CSV хувилбаруудтай. Шинэ XLSX-ийг энэ хавтас дотор хийж болно; XLSX-д CSV-ээс давуу эрх өгнө. Seed CSV-ийг input-оос архивлаж гаргасны дараа зөвхөн шинэ XLSX уншина.

Local дата шинэчлээд GitHub руу автоматаар push хийх:

```powershell
py -3 drilling_sync.py --source local --publish
```

Зөвхөн `dist/data.json` болон `dist/data-log.json` commit хийнэ. `main` branch болон `SysMargad/Drilling-Progress` origin шаардлагатай. Бусад staged файлтай үед зогсоно. Force push хийхгүй; GitHub-ийн өөрчлөлттэй зөрвөл local дата, commit-ийг хадгалж алдааг мэдээлнэ. GitHub нэвтрэлт Git Credential Manager эсвэл таны SSH тохиргоогоор ажиллана.

## Google Drive автомат шинэчлэлт

Drive folder: https://drive.google.com/drive/folders/1b3n84juCY9UbrCMz7D6aITuV3lhgbvVI

GitHub Actions-ийн `Sync drilling data from Google Drive` workflow нь **3 цаг тутам** ажиллана (UTC 00, 03, … 21 = UTC+8 08, 11, … 05). GitHub хуваарьт ажлыг хэдэн цагаар хоцроож эхлүүлдэг тул давтамжийг нэмсэн; нэг ажиллагаа ~15 хүснэгт уншдаг тул Drive API-ийн квотод нөлөөгүй. Sync-ийн код эсвэл `input/shift-audit.json` main-д push хийгдэхэд мөн ажиллана. Гараар ажиллуулж болно.

Цооног автоматаар бүртгэгдэнэ:
- Drive-ийн `2026 / <участик> / <цооног>` хавтсанд шинэ цооногийн хавтас (жишээ нь `4. Sant / STDH2601`) үүсэхэд collar файлд мөр байхгүй ч тухайн цооногийг бүртгэнэ (`registered: drive`).
- Collar мөр нэмэгдмэгц тэр мөрийг ашиглана.
- Цооногийн дугаар нь `XXDH` + тоо хэлбэртэй байвал ямар ч участикийнх танигдана.
- Участикийг угтвараар (DTDH, ZHDH, UGDH, STDH) эсвэл Drive-ийн участикийн хавтсын нэрээр тодорхойлно.
- Collar-ын координатыг «671 289.0» гэх мэт зайтай бичсэн ч уншина. Google credential байхгүй үед аюулгүй skip хийнэ; дата өөрчлөгдвөл commit/push болон Pages deploy-ийг нэг workflow дотор гүйцэтгэнэ.

Нэг удаагийн тохиргоо:

1. Google Drive API read-only service account-ийг эх хавтас унших эрхтэй болгоно.
2. Repository → Settings → Secrets and variables → Actions дотор `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON` secret-д credential JSON-ийг хадгална.
3. Actions → Sync drilling data from Google Drive → Run workflow.

Credential болон token-ийг repository файлд хийхгүй. Өмнөх Mapping repository-ийн secret өөр repository-д автоматаар дамжихгүй.

Local Drive sync:

```powershell
py -3 -m pip install -r requirements.txt
$env:GOOGLE_APPLICATION_CREDENTIALS = 'C:\private\google-drive-credentials.json'
py -3 drilling_sync.py --source drive --watch 300 --publish
```

Local watch ажиллахад компьютер асаалттай, процесс ажиллаж байх шаардлагатай. Cloud workflow компьютер унтарсан үед ч credential тохируулсны дараа ажиллана. Site service token шаардлагагүй.

### Цалин, ирц, хоолны зардал

Санхүүгийн эх сурвалж: [Drive-ийн 2. Cost хавтас](https://drive.google.com/drive/folders/1j8QjgqCHBh50pJwl68hBpTCvTu1tUYgj). Автомат шинэчлэлтэд уг хавтсыг GitHub Actions-д хадгалсан `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON` credential-ийн `client_email` хаягт Viewer эрхээр хуваалцана. Google хэрэглэгчээр нэвтэрсэн байх нь Actions service account-д эрх олгохгүй. Хандах эрхгүй эсвэл эх хүснэгт уншигдахгүй үед өмнөх нэгтгэсэн дүнг хадгалж, алдааг Data Log-д тэмдэглэнэ.

Ирцийн нэрийн тааруулалт: `Туслах тогооч` → `Тогоочийн туслах`, `Угаагч` → `Туслах угаагч`, `ХАБЭА мэргэжилтэн` → `ХАБ, Кемп менежер`, `Аж ахуйн ажилтан` → `Кемп бой`, `Жолооч` → `Усны жолооч`. Хүн бүрийн үндсэн цалин = нэрлэсэн сарын цалин / тухайн сарын календарийн хоног × талбайд ажилласан хоног. Эх файлын `Өдрийн` (эсвэл `Урамшуулал`) багана нь үндсэн цалин дээр нэмэх хоногийн урамшуулал. Метрийн бонус = тухайн хүний тариф × ирцтэй өрөм/ээлжийн бодит метр. Нийт цалингийн зардал = (үндсэн цалин + бонус + урамшуулал) × 1.13; нийтэд харагдах гурван бүрэлдэхүүн тус бүрд 13% нэг удаа шингэсэн.

Эх ирцийн тайлбарын дагуу `A`, `W`, `D`, `C13D/N`, `C18D/N` нь талбайн ажилласан хоног; `P` нь үйлдвэрийн ирц тул талбайн өртөгт орохгүй. `F`, `R`, `LV`, `SK`, `N/A`, хоосон нүдийг ажилласан хоногт тооцохгүй. Өрөм/ээлжийн кодтой хүний зардлыг тухайн өрөм/ээлжид, нийт талбайн ажилтны зардлыг хоёр өрөм × хоёр ээлжид тэнцүү хуваарилна. Ирцгүй орон тоонд цалин зохиомлоор нэмэхгүй. Хоол өмнөх тохиролцоогоор нийт 735,000₮/хоног тогтмол.

Эх хүснэгтийн ажилтны нэр, нэг бүрийн цалин, ирцийн мөрийг зөвхөн санах ойд боловсруулна. Нийтэд нээлттэй `dist/data.json`-д зөвхөн огноо, өрөм, ээлжээр нэгтгэсэн үндсэн цалин, бонус, урамшуулал, хоолны дүн бичигдэнэ; Data Log-д мөн хувь хүний мөр, цалингийн дүн оруулахгүй.

Санхүүгийн хуудас Ерөнхий тоймын графиктай адил хамгийн сүүлийн сараар нээгдэнэ. Эх сурвалж бүр өөрийн хугацааг хамарна: ирц (цалин, хоол, бонус, урамшуулал) ирцийн хүснэгтийн нэг сарыг, түлш болон ус бүртгэлтэй өдрүүдийг, алмазан хошууны тооцоо бүх метрийг. Тухайн сарын ирц эсвэл түлшний бүртгэл Drive-д ороогүй бол өрөмдсөн метр болон бүртгэлтэй зардал харагдана; дутуу эх сурвалжийг «синк хийгдээгүй» гэж бичиж, 0 гэж үзэхгүй, ₮/м тооцохгүй.

## Google Chat өдөр тутмын мэдээ

`.github/workflows/chat-report.yml` нь **өдөр бүр 20:00 (UTC+8)** цагт Chat-д хараахан илгээгээгүй бүх ээлжийг `chat_report.py`-оор Google Chat space руу нэг карт болгон илгээнэ. Drive синк эсвэл local `[skip ci]` commit-оор орсон эсэхээс үл хамаарна. GitHub-ийн өөрийн хуваарь 5–7 цаг хоцорч шөнө дунд илгээдэг тул workflow-г Google Apps Script (`chat_trigger.gs`) 19:30–20:00 хооронд эхлүүлж, workflow 20:00 хүртэл хүлээгээд илгээнэ. Шинэ ээлж ороогүй өдөр сүүлийн ээлжийг заасан богино мэдэгдэл илгээнэ. Картад:
- шинэ ээлжүүдийг цооногийн дугаараар бүлэглэсэн жагсаалт: гүний интервал, метр, DT/ST, ROP, өрөмдөгч, тайлангийн зураг;
- өдрийн дүн: өрөм тус бүрийн метрийг 60 м/өдөр нормтой харьцуулна, мэдээ ороогүй ээлжийг тэмдэглэнэ;
- бүх цооногийн ахиц;
- тайлант хугацааны өрмийн гүйцэтгэл.

Санхүүгийн үзүүлэлт картад орохгүй. Илгээсэн ээлж бүрийг өрөм + огноо + ээлж + цооногоор `chat-posted.json`-д бүртгэж commit хийдэг тул нэг ээлж нэг л удаа илгээгдэнэ. Илгээлт амжилтгүй бол бүртгэхгүй, дараагийн удаа дахин оролдоно. Хожим нөхөгдсөн ээлж дараагийн карт дээр гарна.

Нэг удаагийн тохиргоо:

1. Google Chat space → нэр ▾ → Apps & integrations → Webhooks → Add webhook (жишээ нь `Өрөмдлөгийн явц`) → URL-ийг хуулна.
2. Repository → Settings → Secrets and variables → Actions → `GOOGLE_CHAT_WEBHOOK_URL` secret-д URL-ийг хадгална. Webhook URL нь нууц тул repository файлд хийхгүй.
3. 20:00-ийн trigger:
   - GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Repository access: Only select repositories → `Drilling-Progress`; Permissions → Actions: Read and write. Хугацаа дуусахад Apps Script алдааны имэйл илгээнэ, шинэ token үүсгэж солино.
   - [script.google.com](https://script.google.com) → New project → `chat_trigger.gs`-ийн агуулгыг `Code.gs`-д хуулна.
   - Project Settings → Script Properties → `GITHUB_TOKEN` нэртэй token-ийг хадгална. Token-ийг кодонд бичихгүй.
   - Editor-оос `install` функцийг нэг удаа Run хийж эрх олгоно. Triggers хэсэгт өдөр бүрийн `postDrillingProgress` гарна.
4. Гараар илгээх: Actions → Post drilling progress to Google Chat → Run workflow. Хоосон орхивол илгээгээгүй ээлжүүдийг, `chat_date`-д огноо (жишээ нь `2026-11-02`) бичвэл тухайн өдрийн бүх ээлжийг дахин илгээнэ.

Дараагийн картыг local-аар урьдчилж харах (юу ч илгээхгүй, бүртгэхгүй):

```powershell
py -3 chat_report.py --dry-run
py -3 chat_report.py --date 2026-11-02 --dry-run
```

Илгээлтийг workflow-оор хийнэ: local-аар илгээвэл `chat-posted.json`-ийг commit хийхгүй бол workflow дахин илгээнэ.

## Өгөгдлийн шалгалт

2026.10.27-ны хэрэглэгчийн дүрэм: эх мөрийн DT эсвэл нийт ажилласан цаг хоосон бол тухайн утгыг 12 цаг гэж тооцно. Эдгээр мөрийг тайлбар болон syncWarnings-д таамагласан гэж тэмдэглэнэ; ил тод 0 болон бүртгэсэн цагийг хэвээр хадгална. ST/RT хоосон бол null хэвээр. Өмнө баталгаажсан тусгай засварууд хүчинтэй. Цагийн зөрчил, буруу утгыг энэ дүрмээр далдлахгүй.

```powershell
py -3 -B -m unittest test_drilling_sync test_shift_audit -v
py -3 -B -m unittest test_october_audit -v   # 2026.10-ын аудитын snapshot; sync-д ажилладаггүй
py -3 -B validate_data.py
```

Хүснэгтийн нэг мөр шалгалтад тэнцэхгүй бол (жишээ нь гүн/метр зөрүү) зөвхөн тэр мөрийг `rejectedShifts`-д шалтгаан, хүснэгт, мөрийн дугаартай нь бүртгээд бусад мөрийг шинэчилнэ. Өмнө нь нэг буруу мөр бүх шинэчлэлтийг зогсоож, Data Log-д зөвхөн `ValueError` гэж бичдэг байсан. Sync бүхэлдээ унавал Data Log-ийн `validation` талбарт шалтгааныг бичнэ (нууц мэдээлэлгүй validation алдаа л).

Өрөм: C-1800, CSD-1300. STDH2601 тайлангийн C-1600 гэсэн нэр нь C-1800-ийн бичилтийн алдаа байсан (2026.11.05-ны хэрэглэгчийн залруулга). Эх Sheet, зургийн нэр, тайлангийн хавтас болон dashboard-д C-1800 гэж нэгтгэсэн. Импорт хуучин алдаатай нэрийг C-1800 болгож хэвийнжүүлнэ.

Давхардлыг өрөм + огноо + ээлж + цооногоор хасна. Хоосон гүн нь 0 биш, `null` байна. Ээлжийн гүн/метр, ажлын цаг зөрвөл нийтлэхгүй. Collar болон ээлжийн гүнийг хүснэгтэд тус тусад нь харуулна. Өгөгдөл өөрчлөгдөөгүй бол дата файлыг хэвээр үлдээж, бодит уншилтын түүхийг Data Log-д нэмнэ.

Веб нээлттэй үед 60 секунд тутам `data.json`-ийг дахин уншина. GitHub Pages нийтэд нээлттэй: сайт болон repository-д хадгалсан өгөгдлийг хэн ч үзэж болно. Drive эх файлуудын эрх өөрчлөгдөхгүй.

## Харагдац ба Data Log

Талбай: **Нэргүй Өндөр**. Дөрвөн KPI карт нь ерөнхий тойм, цооногийн бүртгэл, ашиглалт болон ROP хэсгийг нээнэ.

Гүйцэтгэлийг Ээлж, Өдөр, 7 хоног, Сар-аар сонгоно. Норм өрөм тус бүрт 30 м/ээлж, 60 м/өдөр, 420 м/7 хоног; сарынх 60 м × календарийн хоног байна. Дутуу 7 хоног/сар бүтэн үеийн нормтой харьцуулагдана.

`dist/data-log.json` нь Python-оор өгөгдөл уншсан сүүлийн 500 бодит үйлдлийг хадгална: хугацаа, local/Drive эх үүсвэр, өөрчлөгдсөн/өөрчлөлтгүй/алдаатай төлөв, файлын тоо, цооног, ээлж, метр. Өмнөх бүртгэгдээгүй түүхийг зохиомлоор нөхөхгүй. Drive синк алдаатай үед өмнөх дата болон алдааны бүртгэл хадгалагдана.

Data Log-ийн мөр бүр тухайн sync-ээр нэмэгдсэн, хасагдсан, өөрчлөгдсөн ээлжийн жагсаалт (`changes`) болон аудитын тоог (`audit`) хадгална. Энэ нь өөрчлөлтийн audit trail.

Сар сонгосон үед Ээлж/Өдөр-өөр харахад сарын бүх ээлж тэнхлэгт байрандаа гарна: тайлангүй ээлж багана үүсгэхгүй, `!` (тайлан дутуу) эсвэл `?` (баталгаажаагүй) тэмдэгтэй. Санхүүгийн дэлгэрэнгүй хүснэгтэд тайлангүй ээлж «Тайлангүй» гэж гарна, 0 м биш.

## QA/QC ээлжийн аудит

Сар бүрийн өдөр × өдөр/шөнө × өрөм нь нэг ээлжийн байрлал (10-р сард 31 × 2 × 2 = 124). Энэ нь өрөмдсөн ээлжийн тоо биш, шалгах календарь. `shift_audit.py` sync бүрт байрлал бүрийг эх баримтаар ангилж `data.json`-ийн `shiftAudit`-д бичнэ:

- `VERIFIED_DRILLING`: ээлжийн мөр Drive-ийн эх тайлантай (зураг) холбогдсон.
- `VERIFIED_NON_DRILLING`: 0 м-ийн тайлан (өргөсгөл, зогсолт, засвар) эсвэл эзэмшигч `input/shift-audit.json`-д нотолгоотой бүртгэсэн тайлангүй ээлж.
- `MISSING_REPORT`: цооногийн гүн тасарсан (метр тайлангүй), эсвэл өрөм дуусаагүй цооног дээр байхад тайлан алга. Тайлангүй метрийг тухайн өрмийн хоосон ээлжид оноож, хэдэн метр гэдгийг бичнэ.
- `SOURCE_CONFLICT`: гүний давхцал, гүн буцсан (огноо/ээлж зөрүү), collar-д бүртгэлгүй эсвэл дууссан цооногийн тайлан, collar-ын гүнгийн зөрүү, хүснэгтүүдийн тоон зөрүү, validation-д тэнцээгүй мөр.
- `UNVERIFIED`: тайлан алга, гүн тасраагүй (нүүлт, зогсолт байж болзошгүй) эсвэл мөр нь эх тайлантайгаа холбогдоогүй.

Тайлангүй ээлжийг хэзээ ч 0 м гэж тооцохгүй. Нэг ээлжид өрөм цооног солих нь алдаа биш («Ээлжийн дотор цооног солигдсон»). Ээлжийн мөрийг эх зурагтай нь цооногийн 02 хавтас дахь `YYYYMMDD_d/n` нэрээр, эсвэл хүснэгтийн «Эх файл» баганад бичсэн файлын нэрээр холбоно. Мөр бүр аль хүснэгтийн аль мөрөөс ирснийг (`sheet`: нэр, tab, мөр) хадгална. Хүснэгтэд ороогүй Drive тайлан (`unlinkedReports`), өрөм нь тодорхойгүй мөр (`unassignedShifts`), хүснэгтүүдийн тоон зөрүү (`sourceConflicts`) аудитад тусдаа гарна. Тэмдэглэл, файлын нэрээр л ялгаатай хуулбар хүснэгтийг зөрчил гэж тооцохгүй.

Эзэмшигчийн баталгаа (`input/shift-audit.json`, `confirmed`): `rig`, `date`, `shift`, `status: VERIFIED_NON_DRILLING`, `reason`, `evidence`, `confirmedBy`, `confirmedAt` заавал. Метр нэмэх, тайлан зохиох боломжгүй; гүний завсартай ээлжид баталгаа хүчингүй.

Dashboard-ийн «QA/QC аудит» цэс: сар, өрмөөр шүүсэн KPI (хүлээгдэж буй ээлж, төлөв бүрийн тоо, тайлангүй метр, сүүлийн амжилттай sync, өрөм тус бүрийн сүүлийн тайлан), өрмийн ээлж бүрийн календарь, дутуу/зөрчилтэй ээлжийн жагсаалт. Ээлж дээр дарахад мөр, шалгалт, эх тайлан, хүснэгтийн мөр болон цооногийн 02 хавтасны холбоос гарна. CSV татаж болно.

Графикийн нийлбэр, норм, leap year болон жилийн заагийн шалгалт:

    node test_chart.cjs
## Цооногийн ахиц ба участик

Талбай нь Нэргүй Өндөр; участик нь Дорнын Төмөр эсвэл Замт Хөндий. Дээд хэсэгт талбай, участик, өрмөөр шүүнэ. Участик болон өрмийн шүүлтүүр KPI, гүйцэтгэл, цооног, ээлжийн бүртгэлд хамт үйлчилнэ.

Цооногийн ахиц зөвхөн Бүртгэлтэй цооног картыг дарахад нээгдэнэ. Цооногийн дугаар сонгоход тухайн мөрийн доор хугацаа–гүний график дэлгэгдэнэ. Гүн нь 0-оос доош хасах утгаар, өдөр/шөнийн ээлжийн дарааллаар дүрслэгдэнэ. Мэдээлэл тасарсан интервалуудыг холбож интерполяц хийхгүй. Ээлжийн мэдээлэлгүй цооногт зохиомол график зурахгүй.
## Drilling Data

Collar-д бүртгэлтэй бүх цооногийг жагсааж, геологийн лог хийхэд хэрэгтэй ямар дата Drive дээр байгааг харуулна:
- collar-ын эцсийн гүн ба координат;
- кернийн зураг (05);
- геологийн лог (04);
- геотехникийн лог (07);
- pXRF (10);
- хазайлтын хэмжилт (03).

Drive синк цооногийн хавтсуудыг аль хэдийн гүйж уншдаг тул эдгээр хавтсын файлын жагсаалтыг `dataInventory`-д нэмэлт Drive хүсэлтгүйгээр хадгална. Зургийг тоогоор, бусдыг файлын нэр болон холбоосоор хадгална.

Тоолох, ангилах дүрэм:
- Зургийг нэрээр нь нэг удаа тоолно: CR2 ба JPG хуулбар, жижигрүүлсэн хуулбар нэг зураг гэж тоологдоно.
- `delete` гэж эхэлсэн файлыг тоолохгүй.
- Геологийн хавтсанд нэрэндээ Log, log, logging, Geolog гэх мэт үг орсон файл байвал геологийн лог байгаа гэж тооцно (Excel, PDF, Google Docs аль ч хэлбэрээр). Холбоос нь `<HOLE>_Geological_Log.xlsx` загвар, эс бөгөөс Excel, эс бөгөөс бусад лог файл руу заана.
- Геотехникийн хавтсанд (07) мөн адил нэрэндээ log орсон файл байвал геотехникийн лог байгаа гэж тооцно. Холбоос нь `<HOLE>_Geotechnical_Log.xlsx` загвар, эс бөгөөс Excel, эс бөгөөс бусад лог файл руу заана.
- Геологийн хавтсанд лог нэртэй файлгүй, зөвхөн зураг эсвэл PDF байвал гар бичмэл гэж тэмдэглэнэ.
- Геотехникийн хавтсанд лог нэртэй файлгүй бол бусад Excel нь Technical Data (загварт хөрвүүлэх) гэж тэмдэглэнэ.
- «Геологийн лог», «Геотехникийн лог» баганад «Хийгдсэн» (ногоон) эсвэл «Хийгдээгүй» (улаан) гэж гарна: 04 / 07 хавтсанд лог нэртэй файл байвал хийгдсэн. Гар бичмэл скан эсвэл Technical Data байгаа ч лог байхгүй бол хийгдээгүй. Хуудасны дээд хэсэгт дууссан цооногоос геологи, геотехник тус бүр хэд нь хийгдсэн, хэд нь хийгдээгүйг тоолно.

Хүснэгтийн сүүлийн хоёр багана нь «Геологийн лог», «Геотехникийн лог». «Лог хийх боломж», «Лог хийгдсэн эсэх» хүснэгтэд гарахгүй, зөвхөн цооног дээр дарахад нээгдэх цонхонд харагдана.

Лог хийх боломжийг гурван зүйлээр тодорхойлно:
- collar-ын эцсийн гүн;
- геотехникийн лог эсвэл Technical Data (хайрцгийн гүн);
- кернийн зураг (AI лог) эсвэл геологийн лог (геологичийн лог). Хоёулаа байвал «Геологич + AI» давхар лог гэж гарна.

Дуусаагүй цооногийг үнэлэхгүй. Файлын агуулгыг шалгадаггүй, зөвхөн нэрээр нь тодорхойлно.

«Лог хийгдсэн эсэх»:
- Collar файлын багийн бүртгэл болох «Geology log», «Geotechnical log», «XRF Combined log» баганаас уншина.
- Геологи ба геотехник хоёулаа Completed бол «Хийгдсэн», нэг нь бичигдсэн бол «Хэсэгчлэн», хоёулаа хоосон бол «Хийгдээгүй» гэж гарна.
- Drive хавтаснаас бүртгэгдсэн цооногт энэ бүртгэл байхгүй тул «Бүртгэлгүй» гэж гарна.

Цооног дээр дарахад хавтас тус бүрийн файлын жагсаалт Drive холбоосын хамт гарна. Участик шүүлтүүр ба газрын зургийн өнгө шинэ участикийг автоматаар нэмнэ. Local CSV горимд өмнөх жагсаалт хэвээр үлдэнэ. Шалгалт: `node test_drilling_data.cjs`.

Логийн бүртгэл (`dist/log-register.json`): NGM лог систем цооногийн геологийн (04) болон геотехникийн (07) логийг хийж Drive-д байршуулахад файлын нэр, холбоос, огноог энд бичнэ. Бүртгэлтэй лог Drive синкийг хүлээлгүй «Хийгдсэн» гэж гарна (тэмдэглэлд «бүртгэсэн <огноо>»). Синкийн дараа Drive дээрх файл нь өөрөө ч лог гэж танигдана.
## Тайлангийн зураг
Гүйцэтгэлийн баганад хулганаа хүргэхэд өрөмдсөн метр, тухайн хугацааны норм, нормоос дутуу/давсан метр болон бүртгэлтэй ажлын тайлбар харагдана. Баганад дарахад нэг зурагтай бол Google Drive дээр шууд нээгдэнэ. Олон ээлж багтсан өдөр, долоо хоног, сард тухайн өрмийн тайлангийн жагсаалтаас сонгоно. 0 метртэй бүртгэл ч сонгох тэмдэгтэй.

Drive collector нь `02.` өдрийн тайлангийн хавтас дахь зургийг цооног + өрөм + огноо + өдөр/шөнөөр тааруулна; давхардлын/архивын хавтсыг алгасна. Local CSV горимд `input/report-index.json` холбоосуудыг ашиглана. Холбоосгүй ээлжийг өөр өдрийн зурагтай орлуулахгүй. Drive-ийн анхны нэвтрэх эрх хэвээр үйлчилнэ.

Drive шинэчлэлт нь эх тайлангийн хоосон ST/RT кодыг `null` хэвээр хадгална. Тэдгээрийг 0 гэж нөхөхгүй. ST нийлбэр дутуу бол сайт `≥` тэмдэгтэй мэдэгдэж буй цагийн нийлбэрийг харуулна. Метр/гүний зөрүү, сөрөг цаг, зайлшгүй DT эсвэл нийт цаг байхгүй мөрийг нийтлэхгүй.

## Санхүүгийн тогтмол зардал

Алмазан хошуу + reaming shell нь 10,000 м төлөвлөгөөний 72,180,000₮ төсвөөс 7,218₮/м гэж тооцно. Огноо/өрөм/ээлж/цооногийн бүртгэлтэй метрээр үржүүлж, нийт зардал, ₮/м, график, задаргаа, дэлгэрэнгүйд нэг удаа оруулна. 0 м-д зардал нэмэхгүй. Энэ нь бодит хошуу солилт/элэгдэл эсвэл ширхэгийн зарцуулалт биш. Штанг, бусад дахин ашиглах багажийг оруулаагүй.

Drive sync нь алмазын эх Google Sheet-ийн «Үнийн санал - 130 мөр»-өөс зөвхөн drill bit / reaming shell мөрүүдийн тоо × үнийг, «Алмаз - огнооны зардал»-аас төлөвлөсөн метрийг уншиж тарифыг шинэчилнэ. Эх нь харагдахгүй үед `input/diamond-budget.json` дахь сүүлд баталгаажсан төсвийг ашиглана; public JSON-д зөвхөн төсөв, тариф, эх холбоосыг хадгална. Дараагийн синк бүрийн шинэ метрээр тооцоо автоматаар өөрчлөгдөнө.
Сайт үндсэн цалин, бонус, урамшууллыг Drive-ийн ирц/тарифаас уншсан нэгтгэлээр авна. `financial-costs.js`-ийн хуучин тогтмол цалингийн утгуудыг сайт цалинд ашиглахгүй; уг туслах модуль зөвхөн түлш/шаврын одоогийн тооцооллыг нийлүүлнэ.

Ус нь зардлын төрөл биш. Дэлгэрэнгүй бүртгэлийн `Усны хэрэглээ (л)` багана литрээр харуулна; дотоод `waterUsageM3` нэгжийг хадгалж UI дээр 1000-аар үржүүлнэ. 2026.11.01-ний хэрэглэгчийн зөвшөөрлөөр 1 рейс = 5,000 л гэсэн баталгаажаагүй багтаамжийн таамаг хэрэглэнэ. Хөрвүүлсэн хэмжээг «таамаг», дутуу ээлжтэй нэгтгэлийг `≥` гэж тэмдэглэнэ. Хэмжээ/нэгж байхгүй мөрийг 0 гэж нөхөхгүй. Усны машины түлшийг өрөмдлөгийн өртөгт оруулахгүй.

### Ээлжийн олголт ба усны рейсийн засвар

`Шатахууны_бүртгэл` Google Sheet-ийн «Ээлжийн олголт», «Усны рейс» tab-уудыг sync бүр уншина. Эхний tab-ийн `Үнэ ₮/л`, хоёр дахь tab-ийн `Литр / рейс (таамаг)` нь засаж болох үндсэн оролтууд. Зөвхөн «Баталгаатай» түлш, «Таамаг» усны мөрүүдийг хэрэглэнэ; «Нягтлах», «Хассан» мөрүүдийг алгасна. Түлшний огноо+өрөм+ээлж давхардвал шинэчлэлтийг алдаатай гэж тэмдэглэнэ. Хоногийн хуучин нийлбэрийг тухайн огнооны бүртгэлтэй ээлжүүдийн нийлбэрээр солино; хоосон ээлжийг нэмж таахгүй. `coverage` нь 4 боломжит ээлжээс хэд бүртгэгдсэнийг харуулна. Усны болон бусад машин нь өрмийн хоёр rig кодын жагсаалтад орохгүй.

Sheet унших боломжгүй үед `input/consumption-corrections.json` snapshot-ийг хэрэглэж Data Log-д fallback болсон тухай тэмдэглэнэ. Энэ snapshot-д хувь хүний нэр, гарын үсэг байхгүй. «Нягтлах мөрүүд» нь дутуу литр, ээлжгүй олголт, давхардсан фото, Collar-д бүртгэлгүй шинэ цооног болон уншигдахгүй гүнийг хадгална. Тодорхой хоёр C-1800 ээлжийг эх тайлангийн «10_Нэмэлт_тайлан» tab-д нэмсэн; цооног/гүн таагаагүй.

Шалгалт: `node test_financial_costs.cjs`.


### Түлш, шаврын тооцоот хэрэглээ

Санхүүгийн самбарын нийт хэрэглээ, зардлын задаргаа, дэлгэрэнгүй бүртгэл болон графикийн тайлбарт түлшийг литрээр, шаврыг кг-аар харуулна. Шаврын задаргаанд 25 кг шуудайд шилжүүлсэн тоо давхар харагдана. Ээлж/өдөр/7 хоног/сар болон өрмийн шүүлтүүрээр нэгтгэл өөрчлөгдөнө.

Түлшийг хамгийн сүүлд шинэчлэгдсэн `Шатахууны_бүртгэл` эхийн `Зарлага (өрөм) (л)` болон `Өрөмийн Зардал (Төгрөг)` баганаас авна. Метрийн норм болон 3,600₮/л таамгийг ашиглахгүй. Зөвхөн тайлант сарын өрөмд олгосон дүнг оруулна; экскаватор, бусад машин, орлого/үлдэгдлийг өрмийн хэрэглээнд нэмэхгүй. Олголт нь савнаас гарсан хэмжээ, хөдөлгүүрийн бодит зарцуулалтын хэмжилт биш.

Эх бүртгэл зөвхөн хоногийн нийлбэртэй тул тухайн өдрийн өрөм/ээлж/цооногийн тайлагнасан ажлын цагаар хуваарилна. Өдрийн тайлан байхгүй бол хоёр өрөм × хоёр ээлжид тэнцүү хуваарилж, бүртгэлтэй олголтыг нийт дүнгээс алга болгохгүй. Сүүлийн өрөмдлөгийн тайлангаас хойших олголтыг мөн харуулна. Хоосон литрийн нүдийг үл мэдэгдэх утгаар хадгалж, ил тод 0-той ялгана. Шинэ синк эх хүснэгтийн литр ба зардлыг татаж, хоногийн болон хуваарилалтын нийлбэрийг шалгана.

Шаврын хэрэглээ нь хэрэглэгчийн баталсан, Following Products эх хүснэгтийн нийт **17 шуудай × 25 кг = 425 кг**, **17 × 330,000₮ = 5,610,000₮**. Шинэ синк бүр эх хүснэгтийн нийт, нэгж үнэ, ээлжийн хуваарилалтыг уншина. Хуваарилалтын нийлбэр эх нийттэй таарахгүй бол шинэчлэлтийг зогсоож өмнөх баталгаатай дүнг хадгална. Өрөм/ээлж/цооног/огноогоор эх хуваарилалтыг хэрэглэж, нэг ээлжийн олон мөрт давхар тооцохгүй. Ээлжийн хэмжээ нь хуваарилсан дүн; шинэ метр нэмэгдэхэд шавар автоматаар өсөхгүй. 27,000₮/м таамгийг хассан.


### Хэрэглэгчийн өгсөн шатахууны нэмэлт бүртгэл

`input/fuel-supplement.json` нь хэрэглэгчийн өгсөн 2026.10.16–22-ны Excel бүртгэлийн зөвхөн өрөмд олгосон 3,958 литрийг хадгална. Эх файлд зардлын багана байхгүй тул хэрэглэгчийн баталсан өмнөх 5,400₮/л үнээр зардлыг тооцсон. Экскаватор, бусад тээврийн хэрэгслийн зарлагыг оруулаагүй. Хоосон ирээдүйн огноог 0 гэж нөхөөгүй.

Local/Drive шинэчлэлтийн дараа энэ нэмэлтийг огноогоор нэгтгэнэ: давхардсан хоногийг нэмэхгүй, нэмэлтийн утгаар солино; өмнөх болон бусад хоногийг хадгална. Ээлжийн хуваарилалтыг шинэ ажлын цагаар дахин тооцно. Нэмэлт нь зөвхөн заасан сард үйлчилнэ. Эдгээр хоногийн засвар ирвэл нэмэлтийг шинэчлэх эсвэл Drive бүртгэлд бүрэн шилжүүлсний дараа файлыг хасна.

### Mapping

Mapping цэс Collar-ийн координаттай цооногуудыг Leaflet газрын зураг дээр харуулна. Нэргүй Өндөрийн `Nergui_undur_2026.gpkg` болон `23099_uchastic_20260806.prj` файлуудаар WGS 84 / UTM zone 49N (EPSG:32649) системийг баталгаажуулсан. Proj4js ашиглаж E/N-ийг WGS84 өргөрөг/уртрагт хөрвүүлнэ. Координатгүй цооногийг цэг зохиож байрлуулахгүй; тусдаа жагсаана. Z байхгүй ч E/N байвал зурагт орно. Талбай, участик, өрмийн шүүлтүүр Mapping-д мөн үйлчилнэ.

Цэг болон жагсаалтаар цооног сонгож, төлөв, гүн, координат, дэлгэрэнгүй мэдээллийг нээнэ. OpenStreetMap болон Esri World Imagery суурь зурагтай; суурь зураг интернет шаарддаг, tile ачаалахгүй үед цооногийн цэгүүд хэвээр байна. Leaflet 1.9.4 (BSD-2-Clause), Proj4js 2.12.1 (MIT) файлууд `dist/vendor` дотор лицензтэйгээ хадгалагдсан. Газрын зургийн цэгүүд Drive синкээр Collar шинэчлэгдэхэд хамт шинэчлэгдэнэ.
